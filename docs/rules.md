# 起课规则定义 v0.1

> 本文规则表和通用算法与当前 `src/rules` 实现一致。实现差异：产品规格曾写随机数范围 1～99，当前代码实际为 1～18；当前只有设备公历日期时间自动换算，没有独立的手工农历输入界面。这些差异仅作记录，未修改规则代码。

## 1. 通用三传算法

宫位数组使用从 0 开始的内部索引，但界面显示从 1 开始计数。第一次计数包含起点。

设体系宫位数为 `N`，输入为正整数 `a、b、c`：

```text
初传索引 = (a - 1) mod N
中传索引 = (初传索引 + b - 1) mod N
末传索引 = (中传索引 + c - 1) mod N
```

这等价于：

- 第一数从大安起数；
- 第二数从初传落宫起数；
- 第三数从中传落宫起数；
- 每一轮都把当前起点计为 1。

计算函数必须返回完整轨迹，而不只返回三个落宫。

## 4. 五行关系

相生：

```text
木生火，火生土，土生金，金生水，水生木
```

相克：

```text
木克土，土克水，水克火，火克金，金克木
```

当前程序对相邻两传使用以下关系枚举：

- `同类`：同五行
- `相生`：前者生后者
- `受生`：后者生前者
- `相克`：前者克后者
- `受克`：后者克前者

解释文本必须根据关系方向生成，不能把“生”和“被生”、“克”和“被克”合并。

## 5. 时间取数

- 使用农历月数字作为第一数。
- 使用农历日数字作为第二数。
- 子、丑、寅、卯、辰、巳、午、未、申、酉、戌、亥分别为 1 至 12，作为第三数。
- 23:00 至次日 00:59 均属子时。
- 公历日期归属默认采用设备民用日期；是否采用“晚子时换日”必须作为未来可配置规则，首版不得暗中换日。
- 自动换算后必须允许用户返回手工农历方式修正。

## 6. 三字取数

- 输入最终必须解析为三个 Unicode 汉字，而不是三个 UTF-16 code unit。
- 先进行词组级繁体转换，再逐字处理。
- 默认转换目标为通用繁体；转换结果由用户确认。
- 每个字显示数据集给出的笔画数，并允许手工覆盖。
- 保存记录时同时保存原字、繁体字、数据集笔画数、人工覆盖值和最终使用值。
- 第一、第二、第三字分别对应第一、第二、第三数。

注意：Unicode `kTotalStrokes` 是规范化笔画数据来源之一，但不应在 UI 中未经验证地宣称所有数值均等同于民间姓名学的康熙笔画。项目采用的数据集需在实现时写明来源、版本和差异说明。

## 7. 规则版本

所有计算结果必须携带 `ruleVersion`。当前版本为 `0.2.0`。任何会改变既有输入结果的修改必须提升规则版本，并保留旧记录原始结果。
