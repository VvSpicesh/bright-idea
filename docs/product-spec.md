# bright-idea 产品规格 v0.1

## 1. 产品目标

提供一个计算过程透明、规则版本明确、适合手机使用的小六壬工具。用户可以快速起课，查看三传和五行关系，保存问题与结果，并在事情结束后复盘。

首版优先保证计算正确、结果可解释和离线可用，不追求自动生成长篇断语。

## 2. 体系选择

首页首先选择规则体系：

1. `六宫小六壬`
2. `九宫小六壬（荀爽体系）`

两种体系共用起课流程，但宫位、五行和解释数据完全隔离。历史记录必须保存当时的体系 ID 和规则版本，后续规则更新不得悄悄改变旧记录。

## 3. 起课方式

### 3.1 任意三数

- 输入三个正整数。
- 不设置无意义的较小上限。
- 禁止 0、负数、小数、空值和非数字。
- 计算前保留用户原始输入。

### 3.2 任意三个汉字

- 输入恰好三个汉字；空格和常规标点不计入字符数。
- 将简体转换成繁体，再取得每个繁体字的笔画数。
- 默认显示：原字、转换结果、每字笔画数。
- 一简多繁或转换不确定时必须让用户确认，不可静默猜测。
- 用户可以在起课前修改繁体字和笔画数。
- 生僻字、异体字或无笔画数据时，要求用户手工输入笔画数。
- 三个最终笔画数作为三数进入相同的起课引擎。

数据实现要求：

- 繁简转换使用可离线运行、许可证允许分发的本地词典，例如 OpenCC。
- 笔画数据必须使用版本化的本地数据集，目标口径为康熙繁体笔画。
- 不依赖在线接口。
- UI 必须显示数据口径及数据版本。

### 3.3 自动随机三数

- 用户主动点击后才生成。
- 每次生成三个 1 至 99 的整数。
- 显示生成的原始数字，允许重新生成。
- 使用浏览器加密随机源；测试中通过依赖注入固定随机值。

### 3.4 当前日期时间

- 读取设备本地日期、时间和时区。
- 自动转换成农历月、农历日和时辰序号。
- 用户确认转换结果后起课。
- 显示公历、农历、时辰、时区和换算规则版本。

### 3.5 手工农历月日时

- 月：1 至 12，并单独标记是否闰月。
- 日：1 至当月实际天数。
- 时辰：子至亥，对应 1 至 12。
- 首版闰月按同名月份数字计算，并在结果中明确标记。

## 4. 计算结果页

结果页按顺序显示：

1. 所问事项；
2. 使用的体系、规则版本和起课方式；
3. 三个原始取数及其来源；
4. 初传、中传、末传；
5. 每一步的起点、计数和落点；
6. 每一传的名称、五行、方位、关键词；
7. 初传到中传、中传到末传的五行关系；
8. 基础白话说明；
9. 保存、复制、重新起课。

不得只给最终结论而隐藏计算过程。

## 5. 历史与复盘

历史记录字段：

- ID、创建时间、设备时区
- 所问事项、事项分类
- 体系 ID、规则版本、起课方式
- 原始输入、转换后输入、三个最终数字
- 初传、中传、末传及五行关系
- 用户备注
- 实际结果、结果日期、复盘备注
- 用户自评：符合、部分符合、不符合、尚未发生

支持搜索、筛选、删除单条记录、导出和导入 JSON。删除和覆盖导入必须二次确认。

## 6. 页面

- 起课首页
- 输入与确认页
- 结果页
- 历史记录页
- 记录详情与复盘页
- 规则说明页
- 设置页

底部导航控制在三个入口：`起课`、`记录`、`规则`。

## 7. 非功能要求

- 手机宽度 360px 起可正常使用。
- 支持触摸操作和系统深色模式。
- 核心操作按钮触控区域不小于 44px。
- 除首次下载外可离线完成起课、查询和记录。
- 不上传问题、历史记录或用户输入。
- 计算逻辑为纯函数，并有完整单体测试。
- 用户刷新或中途退出时保留未完成输入。
- 页面明确提示：传统文化研究与娱乐用途，不构成现实领域的专业建议。

## 8. 首版不做

- 用户账号和云同步
- 在线后端
- 付费功能
- 社区和公开卦例
- AI 自由发挥式断课
- 医疗、法律或投资决策建议
